K-Nearest Neighbors

Author

Daniel Soto

In this note, we use K-Nearest Neighbors to predict whether teens will bring weapons to school.

Setup

We load our usual packages.

library(tidyverse)
library(tidymodels)
library(MLearnYRBSS)
library(themis)        # <- for step_downsample()
library(kknn)
library(janitor)
library(here)

Then we get our cached data.

analysis_split <- readRDS(here("models", "data", "analysis_split.rds"))
analysis_data <- readRDS(here("models", "data", "analysis_data.rds"))

Though the 0/1 split is the same in the training and testing samples, we see that it is especially uneven. KNN is quite sensitive to this — it will just keep predicting the majority class. We will fix this in the recipe with step_downsample().

Workflow

Recipe

Our recipe is as follows:

weapon_recipe <-
    recipe(WeaponCarryingSchool ~ ., data = analysis_train) |>
    step_downsample(WeaponCarryingSchool, under_ratio = 1) |>
    step_zv(all_predictors()) |>
    step_normalize(all_numeric_predictors()) |>
    step_impute_mode(all_nominal_predictors()) |>
    step_impute_mean(all_numeric_predictors()) |>
    step_dummy(all_nominal_predictors())

weapon_recipe
── Recipe ──────────────────────────────────────────────────────────────────────
── Inputs 
Number of variables by role
outcome:    1
predictor: 10
── Operations 
• Down-sampling based on: WeaponCarryingSchool
• Zero variance filter on: all_predictors()
• Centering and scaling for: all_numeric_predictors()
• Mode imputation for: all_nominal_predictors()
• Mean imputation for: all_numeric_predictors()
• Dummy variables from: all_nominal_predictors()

Here,

  • step_downsample() — randomly drops rows from the majority class to fix imbalance. (Critical for KNN.)
  • step_zv() — drops zero-variance predictors (no info, just noise).
  • step_normalize() — mandatory for KNN. Without it, predictors with bigger units dominate the distance.
  • step_impute_*() — KNN can’t compute distance with NAs.
  • step_dummy() — kknn needs numeric predictors only.

Spec — kknn

kknn_spec <-
    nearest_neighbor(
        neighbors = tune()    # ⬅️ we'll tune K
    ) |>
    set_mode("classification") |>
    set_engine("kknn")

Tuning K

Build the tuning grid

We build a tuning grid with odd numbers. This is because with binary classification and odd K, we can never get a “tie vote.”

neighbor_grid <- tibble(neighbors = c(1, 3, 5, 7, 11, 15, 21, 31, 51))

Run the tuning

KNN tuning is fast — no model is actually trained, just distances are computed.

doParallel::registerDoParallel()

set.seed(2023)

knn_tune <- tune_grid(
    kknn_workflow,
    resamples = analysis_folds,
    grid      = neighbor_grid,
    metrics   = metric_set(roc_auc, accuracy)
)

doParallel::stopImplicitCluster()

Making sure our metrics are Interpretable

Of course, with imbalanced outcomes, we cannot trust accuracy alone. Sensitivity and specificity tell the real story.

multi_metric <- metric_set(sensitivity, specificity, accuracy, kap)

multi_metric(
    predictions_testing,
    truth = WeaponCarryingSchool,
    estimate = .pred_class,
    event_level = "second"
)
